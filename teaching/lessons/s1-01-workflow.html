Drive a working OpMode first, then use what you observed to understand its structure.

Simulator first drive

Start with a working robot program. Do not read every line before driving; first learn what the controls and simulator feel like.

Drive in the simulator

  1. Open the repository in Android Studio. Connect the gamepad before launching the simulator.
  2. In the toolbar, select the Simulator run configuration and click the green Run button.
  3. In the simulator Configuration dropdown, choose the preconfigured robot configuration for the lesson OpModes.
  4. In the OpMode list, select [S1-01] Workflow.
  5. Press INIT, then START. Drive slowly and release the controls between each test.

Driving controls

ControlActionTry this
Left stick YForward and backwardMove a little, then release.
Right stick XTurn left and rightTurn in place, then release.
Both sticksCurved motionCombine forward and turning.

Before each test, tell your team what you predict. Afterward, explain what happened. Notice that the telemetry reports the left and right side power, not a command called “forward” or “turn.”

Now navigate the code

  1. Stop the simulator OpMode.
  2. In Android Studio's Project view, expand TeamCode/src/main/java/org/firstinspires/ftc/teamcode/teaching/session1.
  3. Open S1_01_WorkflowTeleOp.java. The @TeleOp name is the text you selected in the simulator.
  4. Find init(). It runs once when you press INIT and prepares the four motors.
  5. Find loop(). It runs repeatedly after START, reads the sticks, calculates left/right power, and updates telemetry.
Pro tip: Press Shift+Shift in Android Studio to open the Search Everywhere window, then type S1_01_WorkflowTeleOp to find the class directly. The Project view is still useful when you want to understand where the file lives.

What you should be able to explain

By the end of this page, every student should be able to launch the simulator from Android Studio, choose the preconfigured robot and lesson OpMode, drive forward and turn, locate the OpMode source, and explain that init() prepares once while loop() repeats during driving.

The next page repeats this workflow on the real robot. The robot configuration is already prepared for Session 1, so students do not upload or edit configuration files.
