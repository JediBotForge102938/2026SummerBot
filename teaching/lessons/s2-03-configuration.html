S2-03 · Working with Hardware Map

Keep the robot, code, and simulator using the same hardware names.

Course map Mission Resources Instructor notes
Robot configuration

A configuration file is the map that tells FTC which device name belongs to which hub port. In this repository, robot-configs\ is the source of record: if the wiring map changes, update the repository copy first.

One source of record

The shared profile is robot-configs\starterbot-drive-only.xml. It records four motors, their names, and their Control Hub ports.

Hub portConfiguration namePhysical position
0left_back_driveLeft rear
1right_back_driveRight rear
2right_front_driveRight front
3left_front_driveLeft front

Java code uses the configuration names, not the port numbers. This is why left_front_drive must be spelled exactly the same in the XML and in the OpMode.

When the robot is updated

When the prepared TeamCode run configuration updates the robot, it also restores the configuration from robot-configs\. Important: any configuration changes made on the Driver Station will be overwritten the next time the robot is updated.

Use Driver Station to select the profile, but make lasting configuration changes in the repository source of record with instructor guidance.

Why the simulator matches

The simulator also starts from the same XML. During its build, Gradle copies starterbot-drive-only.xml into the simulator resources. The StarterBot simulator loads that resource and creates its named motors from the file.

That gives us one map used in two places:

PlaceHow it uses the map
Physical robotThe upload script copies the XML to the Control Hub.
SimulatorThe simulator build packages the XML and loads its motor names and ports.
OpMode codehardwareMap looks up the names from the XML.

If the repository XML is correct, the simulator is a useful check before using the robot. If the XML is wrong, both paths can be wrong in the same way.

What you should be able to explain

By the end of this lesson, every student should be able to explain that robot-configs\ is the source of record, predict that updating the robot overwrites Driver Station configuration changes, and explain how the simulator loads the same mapping. .

Configuration is a shared contract: the XML names, the OpMode names, and the physical wiring must agree.
