Robot sensors · IMU

Start with the sensor and the robot's axes. Then connect yaw to heading and watch all three orientation readings change as you rotate the robot by hand.

What is an IMU?

IMU means Inertial Measurement Unit. It is a small motion-sensing package built into this robot's Control Hub. Inside, accelerometers sense acceleration (including the pull of gravity), while gyroscopes measure how quickly the Hub is rotating. The FTC software processes these measurements into useful orientation readings. The programming interface exposes the Hub's built-in sensor as an IMU.

Think of it as a way for the robot to estimate how it is oriented and rotating—not a camera that sees the field, a GPS that locates the robot, or an encoder that counts wheel movement. The FTC SDK notes that yaw can drift over time, so the IMU is not a perfect compass or an absolute field-position sensor. See NYU's introduction to accelerometers, gyros, and IMUs for the sensor basics and the FTC Universal IMU guide for how FTC uses them.

Three rotations: yaw, pitch, and roll

To describe orientation, FTC gives the robot its own three-dimensional coordinate system: forward is +Y, right is +X, and up is +Z. Yaw, pitch, and roll each describe rotation around one of those axes.

RotationRobot axisPicture the robot...Why it matters
YawUp/down (+Z)Turning left or right on the floor, like changing which wall the robot faces.Tracks direction while driving on a flat field.
PitchRight/left (+X)Tilting nose-up or nose-down, such as climbing a ramp.Describes front-to-back tilt.
RollForward/back (+Y)Leaning toward the robot's left or right side.Describes side-to-side tilt.

For FTC's robot axes, yaw is rotation around vertical, pitch around the robot's right-side axis, and roll around its forward axis. Those axis names are more reliable than memorizing a picture of a sensor mounted a particular way; the Hub's physical orientation is configured separately.

Yaw becomes heading

In FTC driving code, heading usually means the robot's yaw angle: which way its front points around the vertical axis. Yaw describes the rotation; heading is the direction value we use in robot logic. On a level field, teams often use those words almost interchangeably.

The number needs a reference direction. It is not automatically “north” or a known spot on the field. This sensor-check program does not reset yaw, so do not expect its first reading to be zero. The FTC SDK can preserve heading between OpModes. In the next lesson, you will choose a field direction as zero before trying field-centric driving.

Use the sensor-check OpMode

  1. Open S3_01_IMUSensorTeleOp.java under TeamCode/src/main/java/org/firstinspires/ftc/teamcode/teaching/session3/. In Android Studio, use Shift+Shift and search for the filename.
  2. In init(), find hardwareMap.get(IMU.class, "imu"). The name imu must match the active robot configuration.
  3. Read the next few lines: this code declares the Hub logo UP and its USB ports FORWARD, then initializes the IMU with that mounting orientation.
  4. In loop(), find the yaw, pitch, and roll telemetry. Each value comes from the same orientation reading, expressed in degrees.
Mounting check: the code only works as intended if the physical Hub matches the declared orientation. With an instructor, compare the actual robot to the code before changing these directions. The BioBuzz configuration identifies its internal sensor as imu.

Make a prediction, then test

  1. Build and deploy the TeamCode app. With an instructor, select the BioBuzz StarterBot robot configuration and [S3-01] IMU Sensor Check.
  2. Press INIT, then START. This OpMode only initializes the IMU and reports telemetry; it does not command the drive motors.
  3. On a clear floor, with an instructor supervising, keep fingers clear of the wheels and mechanisms. Gently rotate the robot by hand while a teammate watches the three readings.
  4. Predict before each movement: which reading should change most when you turn the robot on the floor? What should happen to pitch and roll if the chassis stays level?
  5. Stop the OpMode. If the reading direction or size seems surprising, check the declared Hub mounting with an instructor before changing code.

If the team does not have the BioBuzz robot/configuration available, do the code walk-through only—do not run this OpMode with a different robot profile.
