Button state and speed

First observe the correct button behavior in the solution OpMode. Then run the exercise, reproduce the held-bumper problem, and iterate until the exercise matches the reference.

Use the working reference

  1. Launch the simulator with the Android Studio Simulator run configuration.
  2. Select the preconfigured robot configuration and [S2-02] Speed toggle - Solution.
  3. Press INIT and START. Drive briefly so you can recognize the normal control.
  4. Tap the right bumper once. Confirm that the mode changes once.
  5. Hold the right bumper. Confirm that the mode does not keep changing while the bumper is held.
  6. Release the bumper, then tap it again. Confirm that the next tap changes the mode once.
  7. Stop the OpMode and explain what the solution remembers between loops.

Run and repair the exercise

  1. Select [S2-02] Speed toggle - Exercise and press INIT and START.
  2. Repeat the same tap, hold, release, and tap-again sequence from the solution. Watch for the mode to change repeatedly while the bumper is held.
  3. Stop the OpMode and open S2_02_SpeedToggleExerciseTeleOp.java in the Session 2 package.
  4. Use Search Everywhere with Shift+Shift, or navigate through the Project view.
  5. Compare the exercise with S2_02_SpeedToggleSolutionTeleOp.java. Find the pressed, wasPressed, and slow variables.
  6. Change the toggle condition so it runs only when the bumper is pressed now and was not pressed during the previous loop.
  7. Build and run the exercise again. Repeat the exact reference tests and iterate until tap changes once, hold does not repeat, and the next tap changes the mode once.

What the program remembers

loop() runs many times per second. A button can remain pressed across many loops, so checking only “is it pressed?” repeats the action. Comparing the current value with the previous value detects the transition from released to pressed.

StateMeaning
pressedWhat the bumper says during this loop
wasPressedWhat the bumper said during the previous loop
slowThe mode remembered by the program

What you should be able to explain

By the end of this lesson, every student should be able to use a working OpMode as a behavioral reference, explain why a held button is not the same as a button tap, use a previous-state variable to detect one press, and prove the exercise fix with the same simulator tests.

Use the solution as the reference before changing the exercise. Test both OpModes with tap, hold, release, and tap again so the comparison is fair.
