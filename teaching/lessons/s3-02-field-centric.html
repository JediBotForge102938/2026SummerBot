S3-02 · Robot-centric vs field-centric driving

Use IMU heading to make the gamepad's directions stay aligned with the field as the robot turns.

Course map Mission Resources Instructor notes
IMU · field-centric drive

In S3-01, you watched yaw change as the robot turned. Now connect that reading to two different meanings of “forward”: forward relative to the robot, or forward relative to the field.

Two coordinate frames

A coordinate frame is simply the viewpoint used to describe a direction.

FrameWhat “forward” meansWhat happens when the robot turns?
Robot-centricToward the robot's nose.The forward direction turns with the robot.
Field-centricToward a chosen direction on the field, such as the wall the team calls field-forward.The chosen field direction stays fixed while the robot rotates.

In the S2-01 mecanum lesson, the joystick commands are robot-centric: pushing forward asks the robot to move toward its own front. With field-centric control, pushing forward asks it to move toward the chosen field-forward direction—even when the robot is facing sideways.

Picture it: turn the robot so its nose points toward the field's right wall. Robot-centric forward points toward that wall. Field-centric forward still points in the field direction the team chose as forward.

How the IMU connects the frames

The IMU reports the robot's yaw relative to a zero direction. The drive code uses that angle to convert a joystick direction from the field frame into the robot frame before calculating wheel powers. In this way, the sensor reading lets the robot compensate for its own rotation.

The IMU does not know where the robot is on the field or which wall your team means by “forward.” Before testing, point the robot in the desired field-forward direction and press A to call resetYaw(). That sets the current direction as zero for this control scheme; it does not physically move the robot or establish a permanent field compass direction. Review S3-01 if yaw, heading, or the Hub orientation needs a refresher.

Find the conversion in the code

  1. Open BioBuzzStarterbotTeleopMecanumFieldCentric.java under TeamCode/src/main/java/org/firstinspires/ftc/teamcode/. Use Shift+Shift and search for the filename.
  2. In loop(), find the A-button check. It calls imu.resetYaw() while the button is held; press and release A after setting the reference.
  3. Find driveFieldRelative(). It reads yaw in radians and adjusts the joystick angle by the robot's heading.
  4. Find mecanumDrive(). That method turns the adjusted forward, strafe, and rotate values into four wheel powers.

The transform is the important idea—not the trigonometry yet: the code uses the measured robot heading to express the driver's field-relative intent in directions the robot's wheels can carry out.

Experience field-centric control

  1. With an instructor, use the BioBuzz StarterBot configuration and select Mec BioBuzz StarterBot Field Centric Teleop. This OpMode expects the BioBuzz drive train and mechanisms to be configured.
  2. Clear the driving area. Keep hands and objects away from the robot while it is enabled. Use only small, brief stick movements, and keep the triggers and bumpers released.
  3. Point the robot toward the team's chosen field-forward landmark. Press and release A to set this as zero heading.
  4. Give a brief forward input with the left stick and observe the direction of travel. Stop and let the robot settle.
  5. Use a brief, slow right-stick input to turn the robot about a quarter turn. Release the stick. Predict which way the robot will move if you now push the left stick forward.
  6. Give another brief forward input. In field-centric mode, it should still travel along the original field-forward direction, not toward its newly rotated nose. Compare this with the robot-centric behavior from S2-01.

Stop the OpMode when finished. If the robot's orientation reference was not set or the Hub mounting is wrong, the field-relative direction can be wrong too; return to the sensor-check lesson with an instructor.

Quick retrieval check

Explain to a teammate: What stays fixed in a field-centric frame? What turns with the robot in a robot-centric frame? What measurement lets the code convert between them? What does pressing A establish?

Field-centric controls preserve a chosen field direction, not the robot's location. The driver or code must establish the field-forward reference before the IMU angle can be used that way.
