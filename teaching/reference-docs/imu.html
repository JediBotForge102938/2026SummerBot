Current FTC SDK · Universal IMU

This repository uses the current universal FTC IMU interface. The official FTC Universal IMU guide is the source of truth; this page is a compact companion for the field-centric example.

Read this first

TermMeaning here
IMUInertial Measurement Unit: a sensor package whose accelerometers and gyroscopes help estimate motion and orientation.
YawRotation around the robot's vertical axis; on a flat FTC field, it tracks which direction the robot faces.
PitchRotation around the robot's right-side axis; describes nose-up or nose-down tilt.
RollRotation around the robot's forward axis; describes side-to-side tilt.
HeadingThe direction the robot faces, commonly represented by yaw relative to a chosen zero reference.
Hub orientationThe REV Hub's physical mounting directions, described in code so sensor axes line up with robot axes.
Reset yawSet the current direction as the zero-heading reference. It does not move the robot or set an absolute field direction.

The repository code pattern

In BioBuzzStarterbotTeleopMecanumFieldCentric.java, initialization happens once in init():

imu = hardwareMap.get(IMU.class, "imu");
RevHubOrientationOnRobot orientationOnRobot = new RevHubOrientationOnRobot(
        RevHubOrientationOnRobot.LogoFacingDirection.UP,
        RevHubOrientationOnRobot.UsbFacingDirection.BACKWARD);
imu.initialize(new IMU.Parameters(orientationOnRobot));

The logo and USB directions shown are the mounting assumed by this example. Verify the actual robot before using or changing them.

In the repeating loop(), the sample reports yaw in degrees and resets it when A is pressed:

if (gamepad1.a) {
    imu.resetYaw();
}

telemetry.addData("Heading", "%.1f degrees",
        imu.getRobotYawPitchRollAngles().getYaw(AngleUnit.DEGREES));

Configure the built-in IMU

The BioBuzz robot's internal Control Hub IMU is configured on I2C Bus 0, Port 0 as REV Controller IMU, with the name imu. In Driver Station, use Configure Robot → Control Hub Portal → I2C Bus 0 → Port 0, select that device, name it imu, then save and activate the configuration.

The repository profile robot-configs/biobuzz-starterbot.xml must retain the same mapping:

<ControlHubImuBHI260AP name="imu" port="0" bus="0" />

The port and bus attributes are both required in this XML entry. Without a port, the FTC SDK reads the missing value as invalid and can fail when the OpMode initializes the IMU.

If the reading seems wrong

  1. Confirm the selected robot configuration contains the REV Controller IMU on I2C Bus 0, Port 0, named imu.
  2. Check the repository XML entry includes both port="0" and bus="0".
  3. Compare the actual Hub mounting with the LogoFacingDirection and UsbFacingDirection in code.
  4. Check that the robot is being rotated around its vertical axis; forward motion alone is not a yaw turn.
  5. Remember the heading can start away from zero and yaw can drift slowly. Use resetYaw() to choose a fresh reference when appropriate.
  6. Check units at the call site: telemetry uses degrees; the field-centric math reads radians.
Reset yaw while the robot is not rotating, and release the A button after the reset. This example checks the button continuously while it is held.
