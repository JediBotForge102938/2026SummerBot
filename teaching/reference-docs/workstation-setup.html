Member setup guide

From a new laptop to a running robot program.

Follow these steps in order on a Windows workstation. The repository includes both the Android Robot Controller project and a desktop simulator.

Install the required tools

Install Git, Android Studio Panda 4 Patch 1 (2025.3.4.7), and Liberica JDK 17 Full. The full JDK distribution includes the JavaFX runtime needed by the desktop simulator. We pin Panda for workstation consistency even though newer Android Studio release families are available.

On Windows, WinGet can install all three:

winget install --exact --id Git.Git --accept-package-agreements --accept-source-agreements
winget install --exact --id Google.AndroidStudio --version 2025.3.4.7 --accept-package-agreements --accept-source-agreements
winget install --exact --id BellSoft.LibericaJDK.17.Full --accept-package-agreements --accept-source-agreements
If WinGet is not available. Install App Installer from the Microsoft Store, then open a new PowerShell or Windows Terminal window and run the commands again.

Open Android Studio once after installation and allow it to complete its first-run setup. Accept the recommended Android SDK components. Confirm the installed version is Panda 4 Patch 1 (2025.3.4.7) before opening the project.

Get the repository

Keep team projects in one easy-to-find folder. We recommend Documents\FTC.

  1. Open File Explorer and create a folder named FTC inside your Documents folder.
  2. Open the new FTC folder.
  3. Right-click an empty area and choose Open in Terminal.

In the terminal window, clone the repository with its pinned virtual_robot submodule. This creates a new 2026SummerBot folder inside Documents\FTC:

git clone --recurse-submodules https://github.com/JediBotForge/2026SummerBot.git
Choose the folder, not a file. Do not clone the project inside another repository, the Android Studio installation folder, or the Downloads folder.

If you already cloned the repository without submodules, open the 2026SummerBot folder in File Explorer, choose Open in Terminal, and run:

git submodule update --init --recursive
Keep the submodule pinned. Do not edit files inside third_party/virtual_robot for normal team work. The root project supplies the configuration used by our simulator.

Open the project in Android Studio

  1. Start Android Studio and choose Open.
  2. Select the repository folder, not the TeamCode folder.
  3. Wait for Gradle sync to finish before running anything.
  4. If Android Studio asks to use a different JDK, select the installed JDK 17.

Run the desktop simulator

  1. Connect a gamepad before launching the simulator.
  2. In Android Studio, open the run-configuration dropdown in the top toolbar and select Simulator.
  3. Click the green Run button in the toolbar to launch that configuration.
  4. Choose StarterBot from the simulator Configuration dropdown.
  5. Select a teaching OpMode, then press INIT and START.

Press Start+A on a controller to assign it to gamepad 1, or Start+B to assign it to gamepad 2.

For the simulator's on-screen gamepad, edit Simulator/src/main/java/local_simulator_config/Config.java, set USE_VIRTUAL_GAMEPAD to true, and restart the simulator. The team default is false, which uses physical gamepads.

Open the simulator reference for controller details and troubleshooting.

Deploy to the Control Hub

  1. Connect the REV Control Hub to the computer.
  2. In Android Studio, open the run-configuration dropdown in the top toolbar and select TeamCode.
  3. Click the green Run button in the toolbar to build, install, and launch the Android Robot Controller app.

The Simulator and TeamCode entries are dedicated run configurations. Use the simulator for practice and the TeamCode configuration for the physical robot.

Open the upload reference for the team configuration procedure.

Continue learning

Once the simulator launches, start with Session 1: From INIT to LOOP. It introduces the simulator workflow before asking you to change code.
